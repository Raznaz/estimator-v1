## Purpose

Управление очередью тикетов комнаты через REST — вне активной сессии
голосования: подготовка списка задач до refinement, просмотр очереди и фиксация
итоговой оценки после обсуждения.

## ADDED Requirements

### Requirement: Создание тикета в комнате

Система SHALL позволять владельцу комнаты создать тикет, указав комнату и
необязательный заголовок.

Тикет добавляется в конец очереди комнаты. Если заголовок не передан или состоит
только из пробелов, система SHALL присвоить тикету автоматический заголовок.
Созданный тикет SHALL иметь статус `PENDING` и незаполненную финальную оценку.

#### Scenario: Владелец создаёт тикет с заголовком

- **GIVEN** пользователь — владелец существующей комнаты
- **WHEN** он создаёт тикет в этой комнате с заголовком «Авторизация по SSO»
- **THEN** возвращается `201` и созданный тикет
- **AND** тикет имеет переданный заголовок, статус `PENDING`, пустую финальную
  оценку и порядковый номер на единицу больше последнего тикета комнаты

#### Scenario: Заголовок не передан

- **GIVEN** пользователь — владелец существующей комнаты
- **WHEN** он создаёт тикет без заголовка
- **THEN** возвращается `201` и тикет с непустым автоматически присвоенным
  заголовком

#### Scenario: Создание без токена

- **WHEN** запрос на создание тикета приходит без токена доступа
- **THEN** возвращается `401` и тикет не создаётся

#### Scenario: Создание не владельцем

- **GIVEN** пользователь аутентифицирован, но не является владельцем комнаты
- **WHEN** он создаёт тикет в этой комнате
- **THEN** возвращается `403` и тикет не создаётся

#### Scenario: Комната не существует

- **GIVEN** пользователь аутентифицирован
- **WHEN** он создаёт тикет в несуществующей комнате
- **THEN** возвращается `404` и тикет не создаётся

### Requirement: Просмотр очереди тикетов комнаты

Система SHALL возвращать список тикетов комнаты, упорядоченный по позиции в
очереди по возрастанию.

Список SHALL быть доступен любому участнику комнаты, а не только владельцу.

#### Scenario: Участник запрашивает очередь

- **GIVEN** комната содержит три тикета, добавленных в известном порядке
- **AND** пользователь — участник этой комнаты, но не владелец
- **WHEN** он запрашивает список тикетов комнаты
- **THEN** возвращается `200` и все три тикета в порядке их добавления

#### Scenario: Комната без тикетов

- **GIVEN** в комнате нет ни одного тикета
- **WHEN** участник запрашивает список тикетов
- **THEN** возвращается `200` и пустой список

#### Scenario: Запрос без токена

- **WHEN** запрос списка приходит без токена доступа
- **THEN** возвращается `401`

#### Scenario: Комната не существует

- **WHEN** участник запрашивает тикеты несуществующей комнаты
- **THEN** возвращается `404`

#### Scenario: Комната не указана

- **WHEN** запрос списка приходит без идентификатора комнаты
- **THEN** возвращается `400`

### Requirement: Фиксация финальной оценки тикета

Система SHALL позволять владельцу комнаты зафиксировать финальную оценку тикета.

При фиксации система SHALL сохранить переданное значение как финальную оценку и
перевести тикет в статус `ESTIMATED`. Повторная фиксация оценки для уже
оценённого тикета SHALL перезаписывать предыдущее значение.

#### Scenario: Владелец фиксирует оценку

- **GIVEN** пользователь — владелец комнаты, в которой есть тикет со статусом
  `VOTING`
- **WHEN** он фиксирует для этого тикета оценку `8`
- **THEN** возвращается `200` и обновлённый тикет
- **AND** тикет имеет финальную оценку `8` и статус `ESTIMATED`

#### Scenario: Переоценка уже оценённого тикета

- **GIVEN** тикет уже имеет финальную оценку `5` и статус `ESTIMATED`
- **WHEN** владелец фиксирует для него оценку `13`
- **THEN** возвращается `200`
- **AND** финальной оценкой тикета становится `13`

#### Scenario: Фиксация не владельцем

- **GIVEN** пользователь аутентифицирован, но не является владельцем комнаты
- **WHEN** он фиксирует оценку тикета этой комнаты
- **THEN** возвращается `403` и оценка не сохраняется

#### Scenario: Фиксация без токена

- **WHEN** запрос на фиксацию оценки приходит без токена доступа
- **THEN** возвращается `401` и оценка не сохраняется

#### Scenario: Тикет не существует

- **GIVEN** пользователь аутентифицирован
- **WHEN** он фиксирует оценку несуществующего тикета
- **THEN** возвращается `404`

### Requirement: Финальная оценка соответствует шкале комнаты

Система SHALL принимать в качестве финальной оценки только значение, входящее в
шкалу оценки той комнаты, которой принадлежит тикет.

Спецкарты «неизвестно» (`?`) и «перерыв» (`☕`) не являются оценкой и SHALL
отклоняться как финальное значение, несмотря на присутствие в шкале.

#### Scenario: Значение вне шкалы комнаты

- **GIVEN** комната использует шкалу Фибоначчи, в которой нет значения `7`
- **WHEN** владелец фиксирует для тикета этой комнаты оценку `7`
- **THEN** возвращается `400` и оценка не сохраняется

#### Scenario: Значение из другой шкалы

- **GIVEN** комната использует шкалу Фибоначчи
- **WHEN** владелец фиксирует оценку `XL` — значение из шкалы футболок
- **THEN** возвращается `400` и оценка не сохраняется

#### Scenario: Спецкарта как финальная оценка

- **GIVEN** комната использует шкалу, содержащую спецкарту `?`
- **WHEN** владелец фиксирует для тикета оценку `?`
- **THEN** возвращается `400` и оценка не сохраняется

#### Scenario: Пустое значение оценки

- **WHEN** владелец фиксирует для тикета пустое значение оценки
- **THEN** возвращается `400` и оценка не сохраняется

### Requirement: Синхронизация REST-изменений с участниками комнаты

Система SHALL рассылать всем подключённым участникам комнаты актуальное
состояние комнаты после каждого успешного изменения тикетов через REST.

Требование распространяется на создание тикета и фиксацию финальной оценки.
Запрос списка тикетов состояние не меняет и рассылку SHALL NOT вызывать.
Неуспешный запрос (ошибка прав, валидации или отсутствующий ресурс) рассылку
SHALL NOT вызывать.

#### Scenario: Создание тикета доходит до участников

- **GIVEN** участник подключён к комнате и получает её состояние
- **WHEN** владелец создаёт в этой комнате тикет через REST
- **THEN** участник получает обновлённое состояние комнаты, содержащее новый тикет

#### Scenario: Фиксация оценки доходит до участников

- **GIVEN** участник подключён к комнате и получает её состояние
- **WHEN** владелец фиксирует финальную оценку тикета через REST
- **THEN** участник получает обновлённое состояние комнаты с этой оценкой

#### Scenario: Отклонённый запрос не рассылается

- **GIVEN** участник подключён к комнате
- **WHEN** не-владелец пытается создать тикет и получает `403`
- **THEN** участникам комнаты не рассылается обновление состояния

#### Scenario: Чтение списка не вызывает рассылку

- **GIVEN** участник подключён к комнате
- **WHEN** кто-либо запрашивает список тикетов комнаты
- **THEN** участникам комнаты не рассылается обновление состояния
